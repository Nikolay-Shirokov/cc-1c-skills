# /mxl-decompile — Декомпилятор макета в DSL

Принимает Template.xml табличного документа 1С и генерирует компактное JSON-определение (DSL). Обратная операция к `/mxl-compile`.

## Использование

```
/mxl-decompile <TemplatePath> [OutputPath]
```

## Параметры

| Параметр     | Обязательный | Описание                                |
|--------------|:------------:|-----------------------------------------|
| TemplatePath | да           | Путь к Template.xml                     |
| OutputPath   | нет          | Путь для JSON (если не указан — stdout) |

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/mxl-decompile.ps1" -TemplatePath "<путь>/Template.xml" [-OutputPath "<путь>.json"]
```

## Рабочий процесс

Декомпиляция существующего макета для анализа или доработки:

1. Вызвать `/mxl-decompile` для получения JSON из Template.xml
2. Проанализировать или изменить JSON (добавить области, поменять стили)
3. Вызвать `/mxl-compile` для генерации нового Template.xml
4. Вызвать `/mxl-validate` для проверки

Формат JSON на выходе — тот же DSL, что принимает `/mxl-compile`; его полное описание живёт в навыке `/mxl-compile`.

## Два режима вывода

Скрипт сам выбирает форму записи и печатает её в сводке (`Mode: blocks` / `Mode: flat`):

- **blocks** — `areas: [{ name, rows }]`, области идут подряд. Выбирается, когда
  все области типа `Rows`, не пересекаются и вместе покрывают все строки.
- **flat** — `rows` (вся сетка) + `namedAreas` (координаты областей). Выбирается,
  когда блочная форма потеряла бы данные: есть области `Rectangle`/`Columns`,
  области пересекаются, покрывают не все строки или заданы вырожденным диапазоном.
  Так выгружаются макеты регламентированных отчётов.

Обе формы принимает `/mxl-compile`, роундтрип сохраняет структуру: именованные
области всех типов, объединения, ячейки-поля ввода (`containsValue` + `valueType`
+ `controlType`), цвета, отступы, `textPlacement`.

Что не сохраняется: рисунки и штрихкоды, фон ячеек, несколько наборов колонок.
