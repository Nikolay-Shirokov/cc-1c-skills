# /cfe-transfer — Перенос правок расширения в конфигурацию

Два режима: `check` — какие правки расширения уже есть в основной конфигурации, а какие ещё нет; `transfer` — перенести их. Рабочий цикл: `check` → `transfer` → `check`.

## Параметры

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `ExtensionPath` | Расширение; для `check` — несколько через запятую или каталог с расширениями (обязат.) | — |
| `ConfigPath` | Основная конфигурация (обязат.) | — |
| `Mode` | `check` / `transfer` | `check` |
| `Name` | Только эти объекты: `Тип.Имя`, через запятую | — |
| `Tag` | Метка для комментария-обрамления перенесённого кода, например номер задачи (`transfer`). Если она нужна проекту, а не передана, навык остановится до записи и скажет об этом | — |
| `Expand` | Раскрыть свёрнутое: объект `Тип.Имя` или путь из заголовка раздела; `*` — всё | — |
| `Limit` / `Offset` | Пагинация тела отчёта | `150` / `0` |
| `OutFile` | Записать отчёт в файл | — |

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/cfe-transfer.ps1" -ExtensionPath src\cfe\extname -ConfigPath src\cf
```

## check

Проверяются все правки: перехватчики, `#Вставка`/`#Удаление`, собственные методы, код модуля вне методов (переменные модуля, основная программа), объекты и подобъекты, правки форм — элементы, свойства, реквизиты, колонки добавленные в реквизит конфигурации, команды, события и правила условного оформления по одному, а также изменения свойств заимствованных объектов (`xr:PropertyState`: переопределение значения `Extended`, расширение типа частями `ExtendValue`). Режимы читаются начиная с формата 2.19; в более старом их нет, и расходящееся значение свойства показывается как снимок момента заимствования. Роли не проверяются. Префикс расширения не мешает: перенесённое без него находится как `(found as Имя)`.

- `[TRANSFERRED]` / `[NOT_TRANSFERRED]` / `[PARTIAL]`
- `[DIVERGED]` — нашлось, но отличается: якорь вставки, тело метода, тип
- `[MISSING_IN_CONFIG]` — нет целевого метода, модуля или объекта
- `[MANUAL]` — свойство заимствованного элемента, которое не переносится: расхождение без режима (`no override mode` или `this format has no override modes`), `Notify` (`the platform only warns`), режим `Extended` у свойства, которому переопределение не положено, одиночный `Extended` у `Type`, значение не скалярное, свойства нет в конфигурации. Ничего не пишется, причина в строке
- `[TEMPORARY]` — помечено как не для переноса: комментарий `// Временно: <причина>` или `// Не переносить: <причина>` над методом или на строке `#Вставка`/`#Удаление`. Для элементов формы — `// Не переносить элементы формы: <имена через запятую> — <причина>` в первых строках модуля формы. В остаток и exit code не входит; если всё же перенесено — `[TRANSFERRED] … (marked temporary)`
- `! Имя` — элемент есть в форме конфигурации на момент заимствования, а в форме расширения его нет: заимствованный элемент удалить нельзя, значит форма конфигурации с тех пор изменилась
- `(heuristic: k/n lines)` — для `&Перед`/`&После`/`&Вместо`, обработчиков форм и кода модуля вне методов. Строки кода найдены по порядку, вердикт приблизительный.

Итог — в конце. Если отчёт большой, детали опускаются: запроси их через `-Name` (несколько объектов через запятую).

Exit code `1`, если перенесено не всё.

## transfer

Пишет в конфигурацию то, что `check` считает неперенесённым: правки `&ИзменениеИКонтроль`, собственные методы, переменные и основную программу модуля, код перехватчиков `&Перед`/`&После`/`&Вместо` (встаёт в тело исходного метода) и структуру заимствованной формы — новые элементы, реквизиты с колонками, команды, свойства, перемещения, правила условного оформления; событие формы, элемента и действие команды с `callType` встают в тело обработчика конфигурации, как `&Перед`/`&После`/`&Вместо`. `callType` — перехват, только если в конфигурации есть что перехватывать: у нового события или новой команды расширения его нет, они переносятся как свои — событие в `Form.xml`, команда с действием без `callType`, обработчик отдельным методом в модуль формы, в область роли.

Кроме кода переносятся XML-метаданные заимствованного объекта: собственные реквизиты объекта, собственные реквизиты (колонки) заимствованной табличной части, свои табличные части целиком и состав заимствованной подсистемы. Идентификаторы у перенесённого новые, принадлежность расширению (`ObjectBelonging`, `ExtendedConfigurationObject`) снимается, имя — без префикса, по тому же правилу, что у кода. **Значения при этом не переносятся**: то, что расширение записало в свои реквизиты, остаётся в его колонках и пропадает при отключении расширения. Поэтому в отчёте — блок `!!! Stored data is NOT migrated:` со списком перенесённого: скопируй значения в реквизиты конфигурации до отключения расширения. Собственные формы, макеты и команды (файловые подобъекты) не переносятся — `[MANUAL]`.

Изменения уже существующих элементов тоже переносятся, если расширение объявило их режимом: `Extended` у скалярного свойства заменяет значение в **существующем** элементе конфигурации (uuid, имя и `ExtendedConfigurationObject` не трогаются), а расширение типа (`MultiState`/`ExtendedProperty`) сливает недостающие типы из `ExtendValue` в `<Type>` конфигурации с их квалификаторами; `CheckValue`/`NotifyValue` — части типа конфигурации, их не добавляем. `Notify` не переносится: платформа только предупреждает, расширение при таком расхождении не применяется, и значение остаётся за конфигурацией. Расхождение без режима переопределением не считается (старый формат — снимок момента заимствования). Всё это показывается `[CONFLICT]`/`[MANUAL]` и не пишется. Повторный запуск безопасен — перенесённое пропускается. Одно расширение за раз.

- `[TRANSFERRED]` — записано сейчас; собственный метод — с указанием имени и области (`(as Имя) -> region …`), перехватчик — с местом (`before` / `after` / `around` / `in place of the original`)
- `[WAITING]` — код использует то, чего в конфигурации ещё нет (`waits for: …`): собственный метод, который в этом прогоне не перенесён, реквизит, объект, элемент формы. Перенесётся сам повторным `transfer`, когда это появится в конфигурации
- `[MANUAL]` — навык это не переносит, причина в строке: собственные формы, макеты и команды объекта (файловые подобъекты — перенеси вручную), элемент или свойство формы, которое конфигурация изменила после заимствования, свойство заимствованного элемента без режима переопределения или с `Notify`, режим `Extended` там, где переопределение не поддерживается, одиночный `Extended` у `Type`, нескалярное значение, код вне методов модуля менеджера (платформа такой модуль не применяет), объект на замке поставщика, перехватчик, который при подстановке изменил бы поведение (`Возврат` в `&Перед`, ранний `Возврат` исходного при коде после него, `ПродолжитьВызов` в блоке или с другими аргументами, общая переменная, изменённый `Знач`-параметр); перехватчик, который платформа не применяла (`Знач` не как у исходного)
- `[CONFLICT]` — расходится с конфигурацией; метод, форма или объект метаданных не тронуты. Свойство, изменённое в конфигурации по-своему, остаётся её значением: элемент показывается `[DIVERGED]` с пометкой, что остальное перенесено. Метаданные с тем же именем, но другим типом, — `the type differs`, у изменения свойства — расхождение квалификаторов или отсутствие свойства в конфигурации (`property not changed`)
- запись метаданных проверяется той же сверкой и `/meta-validate` (подсистемы — `/subsystem-validate`): файл пишется, только если сверка видит все изменения на месте, а валидатор не нашёл новых ошибок; иначе не тронут и остаётся `CONFLICT`
- в форме переносятся только свойства со значением на момент заимствования; `0:<uuid>` ссылки на стили и картинки переводятся в имена по `ConfigDumpInfo.xml` конфигурации; перед записью форма проверяется той же сверкой и `/form-validate` — записывается, только если сверка видит все изменения перенесёнными, а валидатор не нашёл новых ошибок; иначе форма не пишется и остаётся `CONFLICT`

У `MANUAL` и `CONFLICT` — строки `from:` (где правка в расширении), `to:` (куда в конфигурации) и `next:` (что делать). В конце — `Changed files:`: проверь эти модули и снова запусти `check`.

Exit code `1`, если остались `WAITING`, `MANUAL` или `CONFLICT`.

Префикс расширения у имён снимается; если имя занято — ставится префикс доработок проекта (`devPrefix`), занято и оно — имя остаётся с префиксом расширения.

Обрамление комментариями, режим удаления, префикс доработок и области задаются в `.v8-project.json` ключами `devPrefix` и `cfeTransfer` (формат — `/db-list`). Без них: без обрамления, удаление комментированием, области — по стандарту структуры модуля.

## Примеры

```powershell
# Перед релизом: всё ли перенесено из всех расширений каталога
... -ExtensionPath src\cfe -ConfigPath src\cf

# Что осталось перенести по одному объекту
... -ExtensionPath src\cfe\extname -ConfigPath src\cf -Name Document.ЗаказКлиента

# Перенести правки модулей
... -ExtensionPath src\cfe\extname -ConfigPath src\cf -Mode transfer -Tag TASK-123
```

Что содержит расширение — `/cfe-diff`.
