# /cfe-transfer — Перенос правок расширения в конфигурацию

Два режима: `check` — какие правки расширения уже есть в основной конфигурации, а какие ещё нет; `transfer` — перенести их. Рабочий цикл: `check` → `transfer` → `check`.

## Параметры

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `ExtensionPath` | Расширение; для `check` — несколько через запятую или каталог с расширениями (обязат.) | — |
| `ConfigPath` | Основная конфигурация (обязат.) | — |
| `Mode` | `check` / `transfer` | `check` |
| `Name` | Только эти объекты: `Тип.Имя`, через запятую | — |
| `Tag` | Метка для комментария-обрамления перенесённого кода, например номер задачи (`transfer`). Если она нужна проекту, а не передана, навык остановится до записи и скажет об этом | — |
| `Expand` | Раскрыть свёрнутое: объект `Тип.Имя` или путь из заголовка раздела; `*` — всё | — |
| `Limit` / `Offset` | Пагинация тела отчёта | `150` / `0` |
| `OutFile` | Записать отчёт в файл | — |

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/cfe-transfer.ps1" -ExtensionPath src\cfe\extname -ConfigPath src\cf
```

## check

Проверяются все правки: перехватчики, `#Вставка`/`#Удаление`, собственные методы, код модуля вне методов (переменные модуля, основная программа), объекты и подобъекты, правки форм — элементы, свойства, реквизиты, колонки добавленные в реквизит конфигурации, команды, события и правила условного оформления по одному, а также изменения свойств заимствованных объектов (`xr:PropertyState`: переопределение значения `Extended`, расширение типа частями `ExtendValue`). Режимы читаются начиная с формата 2.19; в более старом их нет, и расходящееся значение свойства показывается как снимок момента заимствования. Роли не проверяются. Префикс расширения не мешает: перенесённое без него находится как `(found as Имя)`.

- `[TRANSFERRED]` / `[NOT_TRANSFERRED]` / `[PARTIAL]`
- `[DIVERGED]` — нашлось, но отличается: якорь вставки, тело метода, тип
- `[MISSING_IN_CONFIG]` — нет целевого метода, модуля или объекта
- `[MANUAL]` — свойство заимствованного элемента, которое не переносится: расхождение без режима (`no override mode` или `this format has no override modes`), `Notify` (`the platform only warns`), режим `Extended` у свойства, которому переопределение не положено, одиночный `Extended` у `Type`, значение не скалярное, свойства нет в конфигурации. Ничего не пишется, причина в строке
- `[TEMPORARY]` — помечено как не для переноса: комментарий `// Временно: <причина>` или `// Не переносить: <причина>` над методом или на строке `#Вставка`/`#Удаление`. Для элементов формы — `// Не переносить элементы формы: <имена через запятую> — <причина>` в первых строках модуля формы. В остаток и exit code не входит; если всё же перенесено — `[TRANSFERRED] … (marked temporary)`
- `! Имя` — элемент есть в форме конфигурации на момент заимствования, а в форме расширения его нет: заимствованный элемент удалить нельзя, значит форма конфигурации с тех пор изменилась
- `(heuristic: k/n lines)` — для `&Перед`/`&После`/`&Вместо` и обработчиков форм. Строки кода найдены по порядку, вердикт приблизительный.
- `(heuristic: k/n items)` — для кода модуля вне методов. Объявления переменных считаются по одному, операторы сверяются с учётом порядка, повторов и веток препроцессора.

Итог — в конце. Если отчёт большой, детали опускаются: запроси их через `-Name` (несколько объектов через запятую).

Exit code `1`, если перенесено не всё.

## transfer

Пишет в конфигурацию то, что `check` считает неперенесённым: правки `&ИзменениеИКонтроль`, собственные методы, переменные и основную программу модуля, код перехватчиков `&Перед`/`&После`/`&Вместо` (встаёт в тело исходного метода) и структуру заимствованной формы — новые элементы, реквизиты с колонками, команды, свойства, перемещения, правила условного оформления; событие формы, элемента и действие команды с `callType` встают в тело обработчика конфигурации, как `&Перед`/`&После`/`&Вместо`. `callType` — перехват, только если в конфигурации есть что перехватывать: у нового события или новой команды расширения его нет, они переносятся как свои — событие в `Form.xml`, команда с действием без `callType`, обработчик отдельным методом в модуль формы, в область роли.

Кроме кода переносятся XML-метаданные заимствованного объекта: собственные реквизиты объекта, собственные реквизиты (колонки) заимствованной табличной части, свои табличные части целиком и состав заимствованной подсистемы. Идентификаторы у перенесённого новые, принадлежность расширению (`ObjectBelonging`, `ExtendedConfigurationObject`) снимается, имя — без префикса, по тому же правилу, что у кода. **Значения при этом не переносятся**: то, что расширение записало в свои реквизиты, остаётся в его колонках и пропадает при отключении расширения. Поэтому в отчёте — блок `!!! Stored data is NOT migrated:` со списком перенесённого: скопируй значения в реквизиты конфигурации до отключения расширения.

У заимствованного справочника переносятся добавленные расширением управляемые формы, MXL-макеты и вложенные команды. Для каждого файла проверяется содержимое, а для нового имени применяется лестенка префиксов из настроек владельца. Регистрация в `ChildObjects` и файлы публикуются после проверки кандидата. Доступ определяется правилами поддержки справочника. Назначения основных и вспомогательных форм берутся из конфигурации. Стабильный UUID помогает при сверке после переименования и при восстановлении отсутствующей части. Неподдерживаемый формат выводится как `[MANUAL]`.

Из собственных корневых объектов расширения переносятся общие модули, общие команды, справочники, перечисления, константы, определяемые типы, параметры сеанса, функциональные опции и их параметры, подписки на события и регламентные задания. Справочник переносится с реквизитами, табличными частями, модулями объекта и менеджера, управляемыми формами, командами и табличными макетами MXL. Перечисление переносится со значениями и модулем менеджера, константа — с имеющимися модулями менеджера и менеджера значения. Стабильные UUID в пределах целевой конфигурации позволяют находить перенесённое после переименования и дополнять отсутствующие совместимые части. При допереносе значений перечисления сохраняется относительный порядок уже существующих значений. Расхождения выводятся как `[CONFLICT]`. Порядок регистрации учитывает `newObjectPosition` проекта. Для регистрации нового объекта проверяется возможность изменения конфигурации и правила поддержки её корня с учётом `editingAllowedCheck`. Перед отключением или удалением расширения выполни миграцию данных, перечисленных в предупреждении: записей справочников, сохранённых ссылок на значения перечислений и значений констант.

Подписки и задания переносятся после разрешения их зависимостей и проверки экспортного обработчика в основной конфигурации. Подписка сверяется по источникам, событию и обработчику. У задания сохраняются исходные `Use`, `Predefined` и файл расписания, если он есть в выгрузке расширения.

Переносятся также собственные группы команд и общие картинки. Картинка переносится с XML-описанием и исходным изображением или архивом. Пустая картинка из полной выгрузки переносится как один дескриптор. Ссылки в метаданных и прямые обращения через `БиблиотекаКартинок` / `PictureLib` используют фактические имена перенесённых объектов.

Собственные обработки и отчёты переносятся с реквизитами, табличными частями, управляемыми формами, командами, модулями объекта и менеджера. Поддерживаются макеты MXL, СКД, текстовые и двоичные макеты. В назначениях форм и основной СКД, а также в прямых вызовах `ОткрытьФорму` / `OpenForm` с полным путём формы используются целевые имена. СКД копируется с проверкой структуры. Если в запросе, выражении или типе СКД найдено имя, требующее переименования, отчёт показывает `[MANUAL]`. Прочие форматы файлов, в том числе обычные формы и встроенная справка, также требуют ручной проверки.

Переносятся собственные документы, нумераторы, регистры сведений и накопления. У документа проверяются `RegisterRecords`, `BasedOn` и нумератор. У регистров проверяются типы измерений и ресурсов, модуль набора записей и наличие регистратора, если он требуется. Связанные циклом документы и регистры проверяются и записываются одним пакетом. Если участник пакета ждёт разрешения внешней ссылки, снятия блокировки или включения в `-Name`, остальные участники тоже ждут.

Перед отключением расширения перенеси сохранённые документы, записи регистров и движения, перечисленные в предупреждении. Для перенесённых нумераторов проверь продолжение нумерации.

У собственных справочников и планов видов характеристик `Ext/Predefined.xml` объединяется по `Item/@id` с сохранением GUID и иерархии. Совпавший элемент сверяется по родителю и свойствам. Коллизия имени с другим GUID, конфликт кода при включённом контроле уникальности или изменение совпавшего элемента дают `[CONFLICT]`. Типы значений ПВХ и явные обращения к перенесённому владельцу используют целевые имена. Перед отключением расширения проверь привязку предопределённых элементов и перенос связанных данных.

ПВХ и его справочник дополнительных значений при взаимной зависимости проверяются и записываются одним пакетом. В целевой конфигурации сохраняются ссылки `CharacteristicExtValues` и `Owners`.

Ссылки в составе подсистемы, типах реквизитов и ссылочном `FillValue` сверяются по зарегистрированным объектам конфигурации. Точное имя имеет приоритет. При отсутствии цели добавь объект и повтори перенос (`[WAITING]`). При неоднозначности или неполной выгрузке проверь кандидатов и дескрипторы (`[MANUAL]`).

У частично перенесённого общего модуля сверяются свойства, объявления и тела методов. Если совпадают свойства и минимум два содержательных метода, составляющих больше половины исходных, дописываются отсутствующие методы. При неоднозначном совпадении проверь кандидатов в отчёте. Зависимые правки ожидают успешной записи цели.

Изменения уже существующих элементов тоже переносятся, если расширение объявило их режимом: `Extended` у скалярного свойства заменяет значение в **существующем** элементе конфигурации (uuid, имя и `ExtendedConfigurationObject` не трогаются), а расширение типа (`MultiState`/`ExtendedProperty`) сливает недостающие типы из `ExtendValue` в `<Type>` конфигурации с их квалификаторами; `CheckValue`/`NotifyValue` — части типа конфигурации, их не добавляем. `Notify` не переносится: платформа только предупреждает, расширение при таком расхождении не применяется, и значение остаётся за конфигурацией. Расхождение без режима переопределением не считается (старый формат — снимок момента заимствования). Всё это показывается `[CONFLICT]`/`[MANUAL]` и не пишется. Повторный запуск безопасен — перенесённое пропускается. Одно расширение за раз.

- `[TRANSFERRED]` — записано сейчас; собственный метод — с указанием имени и области (`(as Имя) -> region …`), перехватчик — с местом (`before` / `after` / `around` / `in place of the original`)
- `[WAITING]` — код использует то, чего в конфигурации ещё нет (`waits for: …`): собственный метод, который в этом прогоне не перенесён, реквизит, объект, элемент формы. Перенесётся сам повторным `transfer`, когда это появится в конфигурации
- `[MANUAL]` — требуется ручной перенос, причина в строке. Например, формат дочернего объекта пока не поддерживается, объект на замке поставщика, свойство заимствованной формы изменено в конфигурации или перенос перехватчика изменил бы его поведение.
- `[CONFLICT]` — расходится с конфигурацией; метод, форма или объект метаданных не тронуты. Свойство, изменённое в конфигурации по-своему, остаётся её значением: элемент показывается `[DIVERGED]` с пометкой, что остальное перенесено. Метаданные с тем же именем, но другим типом, — `the type differs`, у изменения свойства — расхождение квалификаторов или отсутствие свойства в конфигурации (`property not changed`)
- запись метаданных проверяется той же сверкой и `/meta-validate` (подсистемы — `/subsystem-validate`): файл пишется, только если сверка видит все изменения на месте, а валидатор не нашёл новых ошибок; иначе не тронут и остаётся `CONFLICT`
- в форме переносятся только свойства со значением на момент заимствования; `0:<uuid>` ссылки на стили и картинки переводятся в имена по `ConfigDumpInfo.xml` конфигурации; перед записью форма проверяется той же сверкой и `/form-validate` — записывается, только если сверка видит все изменения перенесёнными, а валидатор не нашёл новых ошибок; иначе форма не пишется и остаётся `CONFLICT`

У `MANUAL` и `CONFLICT` — строки `from:` (где правка в расширении), `to:` (куда в конфигурации) и `next:` (что делать). В конце — `Changed files:`: проверь эти модули и снова запусти `check`.

Exit code `1`, если остались `WAITING`, `MANUAL` или `CONFLICT`.

Префикс расширения у имён снимается; если имя занято — ставится префикс доработок проекта (`devPrefix`), занято и оно — имя остаётся с префиксом расширения.

В BSL переименовываются известные идентификаторы с учётом владельца: локальные методы — по карте своего модуля, квалифицированные вызовы общего модуля — по карте вызываемого модуля, реквизиты — по карте своего объекта или формы. Если параметр метода перекрывает имя общего модуля, вызов через этот параметр сохраняет имя метода переданного объекта. Комментарии и обычные строки сохраняются. При сравнении кода регистр идентификаторов игнорируется, а регистр и пробелы внутри строк, включая многострочные, значимы.

Строковые ссылки обрабатываются у `ОписаниеОповещения` / `CallbackDescription` (включая дополнительный обработчик ошибки), `ПодключитьОбработчикОжидания` / `AttachIdleHandler`, `ОтключитьОбработчикОжидания` / `DetachIdleHandler`, `УстановитьДействие` / `SetAction` и `РеквизитФормыВЗначение` / `FormAttributeToValue`. Учитывается контекст ссылки: в управляемой форме `ЭтаФорма` / `ThisForm` и `ЭтотОбъект` / `ThisObject` обозначают форму, а `Объект` / `Object` — её данные. Типы произвольных переменных и вычисляемые строковые выражения не выводятся.

Если обычный литерал полностью совпал с известным переименовываемым именем, код переносится с `[WARNING]`: фрагмент, возможное переименование и адрес строки в итоговой конфигурации. Число и подробности предупреждений печатаются вне бюджета деталей и повторяются при следующих `check` / `transfer`. Сами предупреждения не меняют exit code и не создают `WAITING`.

Явная ссылка на обработчик с неизвестным владельцем или разными целевыми именами оставляет соответствующую единицу переноса в `MANUAL`. Вызовы ожидают такой метод в `WAITING`, в том числе в основной программе модуля. Поддерживаемый ручной выход: уточнить контекст в расширении либо перенести полный метод под распознаваемым целевым именем, сохранив тело с разрешёнными преобразованиями и вручную проверив внешнюю ссылку. Повторный запуск сравнивает тело и переносит зависимости. Произвольно переписанное вручную тело остаётся расхождением при сверке.

Обрамление комментариями, режим удаления, префикс доработок и области задаются в `.v8-project.json` ключами `devPrefix` и `cfeTransfer` (формат — `/db-list`). Без них: без обрамления, удаление комментированием, области — по стандарту структуры модуля.

## Примеры

```powershell
# Перед релизом: всё ли перенесено из всех расширений каталога
... -ExtensionPath src\cfe -ConfigPath src\cf

# Что осталось перенести по одному объекту
... -ExtensionPath src\cfe\extname -ConfigPath src\cf -Name Document.ЗаказКлиента

# Перенести правки модулей
... -ExtensionPath src\cfe\extname -ConfigPath src\cf -Mode transfer -Tag TASK-123
```

Что содержит расширение — `/cfe-diff`.
