# Расширения конфигурации (CFE)

Навыки группы `/cfe-*` помогают создавать расширения 1С, заимствовать объекты, перехватывать методы, проверять расширения и переносить их правки в основную конфигурацию.

## Навыки

| Навык | Параметры | Описание |
|-------|-----------|----------|
| `/cfe-init` | `<Name> [-ConfigPath <path>] [-Purpose Patch\|Customization\|AddOn] [-CompatibilityMode <режим>]` | Создание XML-исходников расширения |
| `/cfe-borrow` | `-ExtensionPath <path> -ConfigPath <path> -Object "Type.Name" [-BorrowMainAttribute Form\|All]` | Заимствование объектов из конфигурации |
| `/cfe-patch-method` | `-ExtensionPath <path> -ModulePath "Type.Name.Module" -MethodName "X" -InterceptorType Before` | Генерация перехватчика метода |
| `/cfe-validate` | `<ExtensionPath> [-MaxErrors 30]` | Валидация структурной корректности (9 проверок) |
| `/cfe-diff` | `<ExtensionPath> [-Name <Тип.Имя>]` | Обзор изменений расширения |
| `/cfe-transfer` | `-ExtensionPath <path> -ConfigPath <path> [-Mode check\|transfer] [-Name <Тип.Имя>]` | Сверка и перенос кода, форм и метаданных в XML-выгрузку основной конфигурации |

## Рабочий цикл

```
cf-info (версия, совместимость)
    ↓
/cfe-init → создание расширения
    ↓
/cfe-borrow → заимствование объектов из конфигурации
    ↓
/cfe-patch-method → перехват методов
    ↓
/cfe-validate → проверка корректности
```

Для готового расширения выбери навык по задаче. [`cfe-diff`](#cfe-diff--обзор-расширения) показывает, что в нём изменено. [`cfe-transfer`](#cfe-transfer--проверка-и-перенос-в-конфигурацию) сверяет эти изменения с основной конфигурацией и по запросу записывает оставшиеся правки в её выгрузку.

## Типичные сценарии

### Создание расширения для исправления бага

```
> Создай расширение для исправления бага в справочнике Контрагенты,
  конфигурация ERP в C:\cfsrc\erp
```

Claude выполнит:

1. `/cfe-init -Name ИсправлениеКонтрагентов -ConfigPath C:\cfsrc\erp -Purpose Patch` — создать расширение в режиме совместимости основной конфигурации
2. `/cfe-borrow` — заимствовать `Catalog.Контрагенты`
3. `/cfe-patch-method` — создать перехватчик нужного метода
4. `/cfe-validate` — проверить результат

### Добавление реквизита в объект и вывод на форму

```
> Добавь реквизит "ОсновнойПоставщик" (тип СправочникСсылка.Партнеры)
  в справочник Номенклатура и выведи на форму элемента.
  Конфигурация ERP в C:\cfsrc\erp
```

Claude выполнит:
1. `/cfe-init` — создать расширение
2. `/cfe-borrow -Object "Catalog.Номенклатура.Form.ФормаЭлемента" -BorrowMainAttribute Form` — заимствовать форму с реквизитами объекта
3. `/meta-edit` — добавить новый реквизит `Расш1_ОсновнойПоставщик` в Номенклатура
4. `/form-edit` — вывести реквизит на форму
5. `/cfe-validate` — проверить результат

### Анализ существующего расширения

```
> Покажи что изменено в расширении src/
```

Claude вызовет `/cfe-diff` и покажет состав правок по объектам.

### Проверка переноса изменений

```
> Проверь, все ли изменения из расширения перенесены в конфигурацию
```

Claude вызовет `/cfe-transfer` в режиме `check` и покажет остаток по XML-выгрузкам.

## cfe-init — создание расширения

Параметры:

| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `Name` | Имя расширения (обязат.) | — |
| `Synonym` | Синоним | = Name |
| `NamePrefix` | Префикс собственных объектов | = Name + "_" |
| `OutputDir` | Каталог | `src` |
| `Purpose` | Назначение | `Customization` |
| `Version` | Версия | — |
| `Vendor` | Поставщик | — |
| `ConfigPath` | Путь к основной конфигурации, чтобы взять из неё режим совместимости | — |
| `CompatibilityMode` | Режим совместимости | `Version8_3_24` |
| `NoRole` | Без основной роли | false |

Создаёт:
```
<OutputDir>/
├── Configuration.xml         # Свойства расширения
├── Languages/
│   └── Русский.xml           # Язык (Adopted)
└── Roles/                    # Если не -NoRole
    └── <Prefix>ОсновнаяРоль.xml
```

Назначение расширения (`Purpose`):
- `Patch` — исправление ошибок (минимальные изменения, только перехватчики)
- `Customization` — доработка (реквизиты, формы, модули)
- `AddOn` — дополнение (полноценный функционал)

## cfe-borrow — заимствование объектов

Заимствует объекты из основной конфигурации в расширение. Создаёт минимальные XML-файлы с `ObjectBelonging=Adopted` и `ExtendedConfigurationObject`.

Формат `-Object`:
- `Catalog.Контрагенты` — справочник
- `CommonModule.РаботаСФайлами` — общий модуль
- `Enum.ВидыОплат` — перечисление
- `Document.Заказ ;; Catalog.Товары` — несколько объектов через `;;`

Поддерживаемые типы: Catalog, Document, Enum, CommonModule, Report, DataProcessor, ExchangePlan, InformationRegister, AccumulationRegister, AccountingRegister, CalculationRegister, ChartOfAccounts, ChartOfCharacteristicTypes, ChartOfCalculationTypes, BusinessProcess, Task, и другие (44 типа).

### Заимствование формы с реквизитами объекта (-BorrowMainAttribute)

При добавлении нового реквизита на заимствованную форму нужна опция `-BorrowMainAttribute`:
- Без неё форма заимствуется "пустой" — только визуальные элементы, без привязки к данным
- С ней — форма сохраняет `DataPath` привязки к реквизитам объекта (`Объект.XXX`)

Два режима:
- `Form` — заимствует только реквизиты, используемые на форме
- `All` — заимствует все реквизиты объекта (включая не выведенные на форму)

Каскадно заимствует зависимые объекты по типам реквизитов (справочники, перечисления, определяемые типы) как оболочки. Если зависимый объект уже заимствован с содержимым — не перезаписывает его.

## cfe-patch-method — перехват методов

Генерирует `.bsl` файл с декоратором перехвата для заимствованного объекта.

Параметры:

| Параметр | Описание |
|----------|----------|
| `ModulePath` | `Catalog.X.ObjectModule`, `CommonModule.Y`, `Catalog.X.Form.Z` |
| `MethodName` | Имя перехватываемого метода |
| `InterceptorType` | `Before` / `After` / `Instead` / `ModificationAndControl` |
| `Context` | `НаСервере` / `НаКлиенте` / `НаСервереБезКонтекста` |
| `IsFunction` | Добавить `Возврат` |

Типы перехватчиков:

| Тип | Декоратор | Когда использовать |
|-----|-----------|-------------------|
| `Before` | `&Перед` | Выполнить код до вызова оригинального метода |
| `After` | `&После` | Выполнить код после вызова оригинального метода |
| `Instead` | `&Вместо` | Выполнить свой код вместо оригинального метода. Оригинал можно вызвать через `ПродолжитьВызов` |
| `ModificationAndControl` | `&ИзменениеИКонтроль` | Внести правки в копию тела оригинала с маркерами `#Вставка` / `#Удаление` |

Пример генерируемого кода (`Before`):
```bsl
&НаСервере
&Перед("ПриЗаписи")
Процедура Расш1_ПриЗаписи()
	// TODO: код перед вызовом оригинального метода
КонецПроцедуры
```

## cfe-validate — проверки

| # | Проверка | Уровень |
|---|----------|---------|
| 1 | XML well-formedness, MetaDataObject/Configuration, version | ERROR |
| 2 | InternalInfo: 7 ContainedObject, валидные ClassId | ERROR |
| 3 | Extension properties: ObjectBelonging=Adopted, Name, Purpose, NamePrefix, KeepMapping | ERROR |
| 4 | Enum-значения (4 свойства) | ERROR |
| 5 | ChildObjects: валидные типы, нет дубликатов, порядок | ERROR/WARN |
| 6 | DefaultLanguage ссылается на существующий Language | ERROR |
| 7 | Файлы языков существуют | WARN |
| 8 | Каталоги объектов существуют | WARN |
| 9 | Заимствованные объекты: ObjectBelonging=Adopted, ExtendedConfigurationObject UUID | ERROR/WARN |

## cfe-diff — обзор расширения

Укажи путь к XML-выгрузке расширения. Для обзора нескольких расширений передай пути через запятую или укажи общий каталог. Состав правок показан по объектам.

- `[BORROWED]` — перехватчики и собственные методы, собственные подобъекты, изменения состава подсистемы и правки заимствованных форм относительно снимка `BaseForm`. Форму целиком с наложенными правками показывает `/form-info`.
- `[OWN]` — собственный объект расширения и состав его подобъектов.

Для деталей по выбранным объектам передай их имена через запятую в `-Name`. Заимствованные объекты без правок сворачиваются в итоговую строку. Чтобы раскрыть их, передай имя объекта или `"*"` в `-Expand`. Для длинного отчёта используй `-Limit` и `-Offset`. Параметр `-OutFile` сохраняет отчёт в файл.

## cfe-transfer — проверка и перенос в конфигурацию

Оба режима работают с XML-выгрузками. Передай путь к расширению в `-ExtensionPath` и путь к основной конфигурации в `-ConfigPath`.

### check

Режим по умолчанию. Сверяет выгрузки без записи в них. Для сверки нескольких расширений передай их пути через запятую или укажи общий каталог.

```text
/cfe-transfer -ExtensionPath src/cfe/Доработки -ConfigPath src/cf -Mode check -Name Catalog.Номенклатура
```

- `TRANSFERRED` означает, что правка перенесена, `NOT_TRANSFERRED` — что она ещё в остатке, `PARTIAL` — что перенесена только часть.
- `DIVERGED` означает, что найденная правка отличается. `MISSING_IN_CONFIG` означает, что целевой метод, модуль или объект отсутствует. Для `MANUAL` потребуется ручная сверка.
- Совпадение с пометкой `heuristic` можно уточнить, сопоставив исходный и перенесённый код.
- Если остались правки или хотя бы одно имя из `-Name` не найдено, `check` возвращает код `1`. Отчёт перечисляет ненайденные имена.

Используй в `-Name` имена из расширения. Чтобы раскрыть свёрнутые строки, передай в `-Expand` имя объекта, путь раздела из отчёта или `"*"`. `-Limit` и `-Offset` задают размер и смещение страницы. В режиме `check` `-OutFile` сохраняет текущую страницу.

### transfer

Записывает BSL, правки заимствованных форм, добавленные объекты и подобъекты, а также поддерживаемые изменения свойств заимствованных объектов. Например, может перенести новый реквизит и правки формы, которая его использует.

```text
/cfe-transfer -ExtensionPath src/cfe/Доработки -ConfigPath src/cf -Mode transfer -Name Catalog.Номенклатура -OutFile transfer-report.txt
```

1. Начни с `check`. Переноси по одному расширению за запуск. `-Name` отбирает объекты целиком, поэтому для переноса одной правки сначала проверь, что она единственная в остатке по объекту. Если шаблон комментария требует метку, укажи `-Tag`, например номер задачи.
2. Укажи `-OutFile` вне каталога выгрузки, чтобы сохранить полный отчёт этого запуска. Смотри `transferred now` и список изменённых файлов. Код `1` допускает частичную запись.
3. Для `MANUAL` посмотри, какое действие нужно выполнить вручную. Для `CONFLICT` сверь расходящиеся правки по отчёту. Для `WAITING` найди правку или объект, от которых зависит перенос. Взаимозависимые объекты могут потребовать одного запуска со всеми участниками. После устранения причины повтори перенос.
4. Проверь изменённые файлы и повтори `check` с тем же отбором.

**Если расширение меняет структуру хранения данных, до его отключения или удаления согласуй, какие данные и как перенести.** Список затронутых позиций приведён в предупреждении `Stored data is NOT migrated`.

Собственные пользовательские роли проверяются и переносятся по умолчанию. Чтобы включить собственные роли из `DefaultRoles` расширения, укажи `-IncludeDefaultRoles` в обоих режимах. Назначение ролей проверяется отдельно.

### Временные правки и настройки

Для временных правок укажи `// Временно: <причина>` или `// Не переносить: <причина>` над методом или на строке `#Вставка` / `#Удаление`. Для элементов формы добавь в начало её модуля `// Не переносить элементы формы: <имена через запятую> — <причина>`. Такие правки исключаются из остатка. Если правка уже есть в конфигурации, отчёт отмечает её временность.

Целевыми именами, обрамлением кода, удалением и областями управляют `devPrefix` и `cfeTransfer` в [настройках проекта](v8-project-guide.md#перенос-правок-расширения-cfetransfer).

## Связь с другими навыками

- `/cf-info` — получение версии и совместимости конфигурации перед `cfe-init`
- `/meta-compile` — создание собственных объектов расширения (реквизиты, ТЧ)
- `/form-compile`, `/form-edit` — создание и модификация форм расширения
- `/cfe-validate` — всегда проверяйте расширение после изменений
