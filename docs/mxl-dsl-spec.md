# Спецификация MXL DSL — JSON-формат описания табличного документа

Компактный JSON-формат для описания макетов табличных документов 1С (SpreadsheetDocument). Используется навыками `/mxl-compile` (JSON → XML) и `/mxl-decompile` (XML → JSON).

## Пример

```json
{
  "columns": 10,
  "defaultWidth": 30,
  "columnWidths": { "1": 15, "2-8": 40, "9-10": 50 },

  "fonts": {
    "default": { "face": "Arial", "size": 10 },
    "bold": { "face": "Arial", "size": 10, "bold": true },
    "header": { "face": "Arial", "size": 14, "bold": true }
  },

  "styles": {
    "default": {},
    "header": { "font": "header", "align": "center" },
    "label": { "font": "bold" },
    "bordered": { "border": "all" },
    "bordered-right": { "border": "all", "align": "right" },
    "total-right": { "font": "bold", "border": "top", "align": "right" }
  },

  "areas": [
    {
      "name": "Заголовок",
      "rows": [
        { "height": 20, "cells": [
          { "col": 1, "span": 10, "style": "header", "param": "ТекстЗаголовка" }
        ]}
      ]
    },
    {
      "name": "ШапкаТаблицы",
      "rows": [
        { "rowStyle": "bordered", "cells": [
          { "col": 1, "text": "№" },
          { "col": 2, "span": 6, "text": "Наименование" },
          { "col": 9, "text": "Кол-во" },
          { "col": 10, "text": "Сумма" }
        ]}
      ]
    },
    {
      "name": "Строка",
      "rows": [
        { "rowStyle": "bordered", "cells": [
          { "col": 1, "param": "НомерСтроки" },
          { "col": 2, "span": 6, "param": "Товар", "detail": "Номенклатура" },
          { "col": 9, "style": "bordered-right", "param": "Количество" },
          { "col": 10, "style": "bordered-right", "param": "Сумма" }
        ]}
      ]
    },
    {
      "name": "Итого",
      "rows": [
        { "cells": [
          { "col": 8, "span": 2, "style": "total-right", "text": "Итого:" },
          { "col": 10, "style": "total-right", "param": "Всего" }
        ]}
      ]
    }
  ]
}
```

## Верхний уровень

| Поле | Обяз. | По умолч. | Описание |
|------|:-----:|-----------|----------|
| `columns` | да | — | Количество колонок |
| `page` | нет | — | Формат страницы: `"A4-landscape"` (780), `"A4-portrait"` (540) или число. Автоматически вычисляет `defaultWidth` из суммы пропорций `"Nx"` |
| `defaultWidth` | нет | 10 | Ширина колонок по умолчанию. `0` — не задавать ширину вовсе, колонки берут ширину платформы (так устроены многие типовые макеты). Игнорируется если задан `page` и все колонки используют `"Nx"` |
| `columnWidths` | нет | `{}` | Ширины колонок. Ключи 1-based: `"1"`, `"3-14"`, `"5,7,9"`. Значения: число (абсолют) или `"Nx"` (множитель от defaultWidth, напр. `"2x"`, `"0.5x"`) |
| `fonts` | нет | — | Именованные шрифты (если не задано, создаётся Arial 10) |
| `styles` | нет | `{}` | Именованные стили |
| `areas` | да* | — | **Блочный режим**: массив именованных областей (порядок = порядок в документе) |
| `rows` | да* | — | **Плоский режим**: вся сетка документа одним массивом строк |
| `namedAreas` | нет | — | Именованные области с явными координатами (любого типа) |
| `extraMerges` | нет | — | Объединения, не привязанные к ячейке (см. ниже) |
| `languages` | нет | русский | Языки макета (см. ниже) |
| `height` | нет | число строк | Явная высота документа. Нужна для макетов, где строки есть за пределами объявленной высоты |

\* Обязательно ровно одно из `areas` / `rows` — вместе они запрещены.

## Два режима описания макета

**Блочный (`areas`)** — макет собирается из блоков строк, идущих подряд: каждая
область получает свой диапазон строк, области не пересекаются. Подходит для
печатных форм («Заголовок», «ШапкаТаблицы», «Строка», «Итого»).

**Плоский (`rows` + `namedAreas`)** — сетка задаётся целиком, а области
описываются координатами поверх неё. Нужен, когда области пересекаются
(строка многострочной части внутри области печати) или когда есть области типов
`Rectangle` / `Columns` — так устроены макеты регламентированных отчётов, где
имя области совпадает с кодом реквизита формы. `/mxl-decompile` сам выбирает
плоский режим, если блочный не описывает макет без потерь.

## Именованные области (`namedAreas[]`)

| Поле | Обяз. | По умолч. | Описание |
|------|:-----:|-----------|----------|
| `name` | да | — | Имя области |
| `type` | нет | `Rectangle` | `Rows`, `Columns` или `Rectangle` |
| `firstRow` / `lastRow` | для `Rows`, `Rectangle` | `lastRow` = `firstRow` | Диапазон строк, 1-based |
| `firstCol` / `lastCol` | для `Columns`, `Rectangle` | `lastCol` = `firstCol` | Диапазон колонок, 1-based |

```json
"namedAreas": [
  { "name": "ОбластьПечатиПоВысоте", "type": "Rows",      "firstRow": 1, "lastRow": 48 },
  { "name": "ОбластьПечатиПоШирине", "type": "Columns",   "firstCol": 1, "lastCol": 35 },
  { "name": "HZY",                   "type": "Rectangle", "firstRow": 9, "lastRow": 9, "firstCol": 16, "lastCol": 17 }
]
```

Координаты 1-based, как `col` у ячеек (в XML платформа хранит их 0-based —
компилятор пересчитывает сам). Области могут пересекаться в любых сочетаниях.
В блочном режиме `namedAreas` тоже разрешён: координаты считаются по итоговой
сетке, собранной из блоков.

## Рамка по сторонам (`styles.<name>.borders`)

Пара `border` + `borderWidth` описывает только сплошную рамку одной толщины на
все перечисленные стороны. Типовые макеты этим не ограничиваются: одна ячейка
может иметь сплошную рамку слева и пунктирную сверху. Для таких случаев:

```json
"borders": {
  "top":    { "style": "Dotted", "width": 1 },
  "left":   { "style": "Solid",  "width": 1 },
  "right":  { "style": "Solid",  "width": 1 },
  "bottom": { "style": "Solid",  "width": 1 }
}
```

Отсутствующая сторона — рамки нет. `style` — токен платформы как есть
(`Solid`, `None`, `Dotted` и др.), `width` — толщина линии, по умолчанию 1.
Компилятор сам собирает палитру линий из всех использованных пар «толщина+стиль».

`/mxl-decompile` пишет компактную форму, пока все стороны — сплошные линии
одной толщины, и переходит на `borders`, как только это не так.

## Языки (`languages`)

Если не задано, макет объявляется русским, и текст ячеек пишется под `ru`.

| Поле | Описание |
|------|----------|
| `text` | Язык, под которым пишется текст ячейки, заданный строкой |
| `current` | `currentLanguage` макета (по умолчанию — `text`) |
| `default` | `defaultLanguage` макета (по умолчанию — `current`) |
| `list` | Объявленные языки: `{ id, code, description }` |

```json
"languages": {
  "text": "uk",
  "current": "uk",
  "default": "uk",
  "list": [
    { "id": "ru", "code": "Русский",   "description": "Російська" },
    { "id": "uk", "code": "Украинский", "description": "Українська" }
  ]
}
```

Ячейка с текстом на нескольких языках описывается объектом (то же для `template`):

```json
{ "col": 1, "text": { "uk": "Постачальник", "ru": "Поставщик" } }
```

Компилятор сам дописывает в `list` каждый язык, который встретился в тексте
ячеек, `text`, `current` или `default`, но не был объявлен, — иначе платформа
при загрузке не найдёт текст для своего языка и потеряет надписи. Названия
для `ru`/`uk`/`en` подставляются известные, для прочих — сам код языка.

**`text` отдельно от `current` не случайно**: макет может объявлять один текущий
язык, а хранить надписи под другим. `/mxl-decompile` определяет `text` по факту —
берёт язык, под которым записано больше всего текстов, а не то, что объявлено
в `languageSettings` (которого может и вовсе не быть).

## Объединения вне ячеек (`extraMerges[]`)

Обычные объединения задаются на ячейке через `span` / `rowspan`. Но платформа
хранит и объединения, не привязанные к строке — например «объединить колонки
2–3 по всей высоте документа». Для них есть аварийный выход:

```json
"extraMerges": [ { "r": -1, "c": 1, "w": 1, "h": 0 } ]
```

Поля повторяют XML один в один: `r`, `c` — 0-based координаты, `-1` = «все
строки» / «все колонки»; `w`, `h` — размер минус один. Записываются как есть.
`/mxl-decompile` кладёт сюда только те объединения, у которых `r` или `c`
отрицательные, — остальные остаются на ячейках.

## Шрифты (`fonts.<name>`)

| Поле | По умолч. | Описание |
|------|-----------|----------|
| `face` | `"Arial"` | Имя шрифта |
| `size` | `10` | Размер. Бывает дробным (`8.3`, `6.8`) — округлять нельзя |
| `bold` | `false` | Жирный |
| `italic` | `false` | Курсив |
| `underline` | `false` | Подчёркнутый |
| `strikeout` | `false` | Зачёркнутый |
| `ref` | — | Системный шрифт, напр. `"sys:DefaultGUIFont"` |
| `kind` | `"Absolute"` | Вид шрифта: `Absolute` или `WindowsFont` |

Шрифт с `ref`/`kind="WindowsFont"` следует настройкам ОС. У него может не быть
размера вовсе — тогда `size` не задают, и компилятор не выдумывает его.

Шрифт `"default"` используется когда стиль не указывает шрифт явно. Если не определён, создаётся автоматически (Arial 10).

## Стили (`styles.<name>`)

| Поле | По умолч. | Описание |
|------|-----------|----------|
| `font` | `"default"` | Ссылка на имя шрифта |
| `align` | — | `left`, `center`, `right` |
| `valign` | — | `top`, `center`, `bottom` |
| `border` | — | Стороны рамки: `all`, `top`, `bottom`, `left`, `right`, `none`. Через запятую: `"top,bottom"` |
| `borderWidth` | `"thin"` | Толщина рамки: `thin` (1px) или `thick` (2px) |
| `borders` | — | Рамка по каждой стороне отдельно (см. ниже). Перекрывает `border`/`borderWidth` |
| `borderColor` | — | Цвет рамки: `"#000000"`. Если не задан — платформенный по умолчанию |
| `wrap` | `false` | Перенос текста (синоним `textPlacement: "wrap"`) |
| `textPlacement` | — | Размещение текста: `wrap`, `auto`, `cut` |
| `textColor` | — | Цвет текста: `"#FF0000"` |
| `hidden` | `false` | Скрытая ячейка |
| `indent` | `0` | Отступ текста |
| `format` | — | Формат данных 1С: `"ЧЦ=15; ЧДЦ=2"`, `"ДФ=dd.MM.yyyy"` и т.д. |

## Области (`areas[]`)

| Поле | Обяз. | Описание |
|------|:-----:|----------|
| `name` | да | Имя области для `Макет.ПолучитьОбласть("Имя")` |
| `rows` | да | Массив строк |

## Строки (`rows[]`)

| Поле | По умолч. | Описание |
|------|-----------|----------|
| `height` | — | Высота строки (если не задана, используется авто) |
| `rowStyle` | — | Стиль для ВСЕХ колонок (заполняет пустоты рамками) |
| `cells` | `[]` | Массив ячеек |
| `empty` | — | Количество подряд идущих пустых строк (заменяет N отдельных `{}`) |

Строка без `cells` и `rowStyle` → пустая строка. `{ "empty": 3 }` эквивалентно трём `{}`.

## Ячейки (`cells[]`)

| Поле | Обяз. | По умолч. | Описание |
|------|:-----:|-----------|----------|
| `col` | да | — | Позиция колонки (1-based) |
| `span` | нет | `1` | Объединение по горизонтали (количество колонок) |
| `rowspan` | нет | `1` | Объединение по вертикали (количество строк) |
| `merge` | нет | `false` | Записать объединение 1×1 (платформа изредка их хранит; при `span`/`rowspan` не нужно) |
| `fillType` | нет | по содержимому | Явный тип заполнения: `Text`, `Parameter`, `Template`. Нужен только для ячейки, объявляющей тип без содержимого |
| `style` | нет | rowStyle | Стиль ячейки (переопределяет rowStyle) |
| `param` | нет | — | Параметр заполнения |
| `detail` | нет | — | Параметр расшифровки (только с `param`) |
| `text` | нет | — | Статический текст |
| `template` | нет | — | Шаблонный текст с `[Параметр]` |
| `input` | нет | — | Ячейка-поле ввода: `"field"` (поле ввода) или `"checkbox"` (флажок) |
| `valueType` | нет | — | Тип значения поля ввода (только с `input`) |

### Ячейки-поля ввода

`input` делает ячейку редактируемой пользователем — так устроены формы
регламентированных отчётов. В XML это `containsValue` + `valueType` +
`controlType`; GUID типа элемента управления подставляется по имени.

`valueType` — либо строка-сокращение, либо объект:

| Сокращение | Эквивалент |
|---|---|
| `"number(10,0)"` | `{ "type": "number", "digits": 10, "fractionDigits": 0 }` |
| `"string(50)"` | `{ "type": "string", "length": 50 }` |
| `"date"` | `{ "type": "date" }` |
| `"boolean"` | `{ "type": "boolean" }` |

Полная форма объекта: `number` — `digits`, `fractionDigits`, `allowedSign`
(по умолч. `Any`); `string` — `length` (0 = неограниченная), `allowedLength`
(по умолч. `Variable`); `date` — `dateFractions` (по умолч. `Date`).

```json
{ "col": 22, "style": "bordered", "input": "field", "valueType": "number(10,0)" }
```

Поле ввода и содержимое совместимы: ячейка может одновременно нести `text`
(показываемое значение) и `input`.

### Тип заполнения

Определяется автоматически по содержимому ячейки:
- `param` → fillType=Parameter
- `template` → fillType=Template
- `text` → fillType=Text
- ничего → без fillType (пустая ячейка или рамка)

Поле `fillType` перекрывает это правило — оно нужно для ячейки, которая
объявляет тип заполнения, но содержимого не несёт (так бывает в типовых
макетах: пустая ячейка с `fillType=Template`).

## `rowStyle` — автозаполнение

Когда задан `rowStyle`, компилятор создаёт ячейки для ВСЕХ колонок строки. Позиции без явных ячеек заполняются пустыми ячейками с указанным стилем. Это обеспечивает сплошные рамки в табличных строках.

Если в предыдущих строках той же области есть ячейки с `rowspan`, их колонки при автозаполнении пропускаются.

## Ограничения

Текущая версия не поддерживает:
- **Множественные наборы колонок** (второй `<columns>` со своим `id`, на который
  строки ссылаются через `<columnsID>`). Встречается часто — примерно в трети
  макетов конфигурации. `/mxl-decompile` в таком случае предупреждает и
  описывает только основной набор; строки с другим набором получат основную
  геометрию.
- Рисунки (штрихкоды, картинки)
- Фон ячеек
